# Pinned exactly, deliberately.
#
# These were all `>=` ranges until 27 September 2026, on the reasoning that ranges are
# more flexible. For a repository other people clone and build, a range is a supply-chain
# hole: the lock that is supposed to protect them is a lower bound, so tomorrow's build
# can install code that was never tested against this source. `npm ci` already pins the
# frontend through package-lock.json; this is the Python equivalent.
#
# To upgrade: change the pin, then run the full suite (`pytest`) and `pip-audit` before
# committing. A bump that only satisfies the resolver has not been verified.
